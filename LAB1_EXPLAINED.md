# Лабораторная №1: куб на Vulkan — конспект для понимания и защиты

Этот файл описывает текущую ветку **lab-1**. Читай его сверху вниз: сначала общая картина, потом один кадр, затем математика и Vulkan. Не нужно сразу запоминать все названия структур. Важнее уметь рассказать, как из координат куба получается изображение.

**Главная мысль:** куб существует в программе как числа. Каждый кадр C++ считывает параметры, готовит матрицу положения и команды. GPU применяет шейдеры к вершинам, заполняет треугольники цветом, проверяет глубину. Готовое изображение показывается в окне.

## 2. Вся программа одной цепочкой

~~~text
Запуск: создать окно → подготовить Vulkan → загрузить шейдеры и конвейер куба

Каждый кадр:
получить ввод → изменить параметры через ImGui → вычислить MVP
→ записать команды рисования → отправить их GPU
→ построить изображение → показать кадр

Закрытие: уничтожить объекты куба → Vulkan → ImGui → окно
~~~

**CPU** выполняет C++ и готовит задание. **GPU** выполняет шейдеры и строит изображение. Шейдер — программа, запущенная на GPU; он не «передаёт данные на GPU», потому что уже находится на стороне GPU.

## 3. Термины простыми словами

| Термин | Что означает здесь |
| --- | --- |
| Локальная точка | Положение относительно центра куба. Куб занимает диапазон от −1 до 1 по каждой оси. |
| Вершина | Данные об одном угле, прежде всего координаты X, Y, Z. |
| Треугольник | Три выбранные вершины. Из треугольников собраны грани куба. |
| Model | Правило масштаба, поворота и переноса куба в сцене. |
| View | Правило перехода от сцены к взгляду камеры. |
| Projection | Правило получения положения для плоского кадра. |
| MVP | Составное правило `Projection × View × Model`. |
| Вершинный шейдер | Вычисляет положение и цвет вершины на GPU. |
| Растеризация | Находит участки пиксельной сетки, покрытые треугольником. |
| Фрагментный шейдер | Вычисляет выходной цвет фрагмента. |
| Буфер глубины | Хранит глубину поверхности, чтобы дальняя грань не перекрыла ближнюю. |
| Командный буфер | Записанный список указаний для GPU. |
| Конвейер Vulkan | Объект с шейдерами и правилами обработки треугольников. |
| Swapchain | Несколько изображений, которые по очереди готовятся и показываются в окне. |

Точка `(0, 0, 0)` в массиве куба — его **локальный центр**, а не угол монитора. Когда перемещение равно нулю, центр куба совпадает с началом координат сцены. После учёта камеры и проекции он находится примерно в центре изображения.

## 4. Карта файлов

- [`source/main.cpp`](source/main.cpp) создаёт окно и организует цикл кадров.
- [`source/graphics_internal.hpp`](source/graphics_internal.hpp) объявляет общие данные Vulkan: устройство, очередь, размер изображения, framebuffer и командный буфер.
- [`source/graphics_internal.cpp`](source/graphics_internal.cpp) создаёт Vulkan-ресурсы, получает изображение для кадра, отправляет команды GPU и показывает результат.
- [`source/application.cpp`](source/application.cpp) содержит матрицы, состояние куба, ImGui, анимацию, конвейер и команды рисования.
- [`shaders/cube.vert`](shaders/cube.vert) задаёт геометрию и обрабатывает вершины.
- [`shaders/cube.frag`](shaders/cube.frag) выдаёт цвет фрагментов.
- [`CMakeLists.txt`](CMakeLists.txt) собирает C++ и компилирует GLSL-шейдеры.

GLFW отвечает за окно и ввод. Vulkan даёт управление GPU. ImGui создаёт галочки и ползунки. ImGui сам куб не двигает: он меняет переменные C++, которые используются в следующем кадре.

## 5. Подготовка при запуске

В `main.cpp` GLFW создаёт окно 1280×720. Флаг `GLFW_NO_API` означает, что GLFW не создаёт контекст OpenGL: рисование будет выполняться через Vulkan. Callback размера framebuffer сообщает, когда нужно обновить зависящие от размера изображения.

`graphics::internal::initialize()` создаёт `VkInstance`, выбирает физическое устройство, создаёт логическое устройство `VkDevice`, получает графическую очередь, создаёт swapchain, буфер глубины, render pass, framebuffer, семафоры, fence и командные буферы. Эта инфраструктура в основном дана стартовым проектом.

`application::initialize()` загружает два модуля шейдеров и создаёт конвейер куба. Это делается после подготовки Vulkan, потому что конвейеру нужны уже созданные устройство и render pass.

### От GLSL до работающего шейдера

`cube.vert` и `cube.frag` — текстовые программы GLSL. Во время сборки `glslc` преобразует их в `cube.vert.spv` и `cube.frag.spv` — файлы SPIR-V. Функция `loadShader()` в `application.cpp` читает эти двоичные файлы и вызывает `vkCreateShaderModule`. Она **не компилирует** GLSL.

`loadShader()` проверяет открытие файла, положительный размер и кратность четырём байтам, читает данные в `std::vector<uint32_t>` и создаёт `VkShaderModule`. Пути `shaders/...` относительны к текущей рабочей папке, поэтому запускать приложение удобно из корня проекта.

## 6. Геометрия куба: 8 углов, 12 треугольников, 36 элементов

В `cube.vert` есть массив `positions[8]` с восемью разными углами куба. Их координаты — комбинации −1 и 1 по X, Y и Z. Центр куба — `(0,0,0)`, но центр **не является одной из восьми вершин**.

Шесть квадратных граней разбиты по два треугольника: `6 × 2 = 12`. На каждый треугольник приходится три элемента: `12 × 3 = 36`. Массив `indices[36]` выбирает нужные углы для каждого элемента. Например, первые числа `0, 2, 1` задают один треугольник из позиций №0, №2 и №1.

Здесь нет отдельного Vulkan vertex buffer или index buffer для куба. Позиции и индексы записаны **прямо в коде вершинного шейдера**. `gl_VertexIndex` указывает, какой элемент из списка сейчас обрабатывается. Поэтому используется `vkCmdDraw(..., 36, ...)`, а не `vkCmdDrawIndexed`.

## 7. Что происходит в одном кадре

Цикл `while (!glfwWindowShouldClose(...))` в `main.cpp` повторяется, пока открыто окно:

1. `glfwPollEvents()` получает ввод и события окна.
2. ImGui начинает кадр. `application::update(time)` меняет значения ползунков и время анимации.
3. `ImGui::Render()` подготавливает данные интерфейса, но ещё не показывает их физически на мониторе.
4. `graphics::internal::prepare()` получает очередное изображение swapchain и возвращает `FrameData`: framebuffer и командный буфер.
5. `application::render(fd)` рассчитывает MVP и **записывает** команды рисования куба.
6. `graphics::internal::submitAndPresent()` добавляет команды ImGui, отправляет команды GPU и запрашивает показ изображения.

Вызовы `vkCmd*` записывают задание в командный буфер. `vkQueueSubmit` передаёт его GPU. `vkQueuePresentKHR` запрашивает показ готового изображения. Это три разных действия.

## 8. Интерфейс и анимация

В `application::update()` элементы ImGui связаны с переменными `position`, `rotation`, `scale`, `tint` и `use_perspective`. Например, сдвиг ползунка Position меняет три числа C++; он не меняет исходный массив из восьми углов.

`time` приходит из `glfwGetTime()`. Разность с `previous_time` — длительность прошедшего кадра, `delta`. Когда анимация включена:

~~~text
animation_time += delta × animation_speed
~~~

Поэтому движение зависит от прошедшего времени, а не от числа кадров в секунду. `delta` ограничивается сверху до 0.1 секунды, чтобы после задержки не было огромного скачка. При паузе `animation_time` не растёт; одинаковое время даёт одинаковое анимационное положение.

Траектория задана простыми формулами: `cos(t)` и `sin(t)` дают движение в плоскости XZ, `sin(2t)` — вертикальное колебание, а дополнительные углы, зависящие от `t`, вращают куб. Радиус, амплитуда и скорость меняются через ImGui. При `t = 0` дополнительные смещения равны нулю.

## 9. Матрицы: путь от куба к кадру

~~~text
Локальная точка куба
→ Model: где она в сцене?
→ View: где она относительно камеры?
→ Projection: где она окажется в плоском кадре?
~~~

Код объединяет их как `MVP = Projection × View × Model`. При умножении на точку справа первым действует крайний правый множитель, то есть `Model`.

`Mat4` хранит 16 чисел матрицы 4×4 по столбцам: индекс элемента равен `column * 4 + row`. `identity()` создаёт единичную матрицу, оставляющую точку без изменения. `multiply(a,b)` вычисляет произведение двух матриц.

### Model — положение фигуры

`translate()` создаёт перенос. `rotateX/Y/Z()` поворачивают вокруг соответствующих осей. Углы из ImGui измеряются в градусах, а `sin` и `cos` используют радианы, поэтому код умножает градусы на `π/180`. `nonUniformScale()` позволяет отдельно изменить размер по X, Y и Z.

Матрица модели собирается в порядке `T × Rz × Ry × Rx × S`. Для точки это означает: сначала масштаб, затем повороты, затем перенос. Масштаб и поворот выполняются относительно локального центра `(0,0,0)`; перенос ставит уже преобразованный куб в сцену. Исходные восемь позиций остаются неизменными.

### View — взгляд камеры

В коде `view = translate(0,0,-6)`. Это удобно понимать как камеру около мировой точки `(0,0,6)`, направленную к центру сцены вдоль отрицательной Z. Куб около мирового нуля оказывается перед камерой.

### Projection — перспектива или ортография

`use_perspective` выбирает одну из двух функций. Обе получают `aspect = width/height`, чтобы окно другой формы не искажало куб.

- `perspective()`: угол обзора 45°, `near = 0.1`, `far = 100`. Дальние части выглядят меньше.
- `orthographic()`: половина видимой высоты 2.5, те же границы глубины. Размер не уменьшается только из-за удаления от камеры.

Математическая причина перспективы: после умножения на перспективную матрицу четвёртая координата становится `w = -z` в координатах камеры. GPU делит положение на `w`. Поэтому горизонтальное положение зависит примерно от `x / расстояние`. В ортографической проекции `w` остаётся 1, поэтому расстояние не влияет на видимый размер.

`near` и `far` задают границы видимой глубины и помогают перевести глубину в диапазон Vulkan около 0..1. Буфер глубины не следует путать с глубиной цвета.

## 10. Как MVP и цвет передаются шейдеру

`PushData` содержит матрицу `mvp` (16 чисел float = 64 байта) и цветовой множитель `tint` (4 числа float = 16 байт), всего **80 байт**. `static_assert` проверяет размер при компиляции. В `cube.vert` объявлен соответствующий блок `layout(push_constant) uniform DrawData`.

`VkPipelineLayout` заранее описывает, что вершинному шейдеру доступен диапазон push constants размером 80 байт. Это **договор о формате**, а не сами значения. Каждый кадр `vkCmdPushConstants` передаёт актуальные MVP и tint для рисования.

~~~text
Pipeline layout → какие данные можно передать
vkCmdPushConstants → значения для данного кадра
Vertex shader → использование этих значений
~~~

Собственного `VkDescriptorSet` для куба здесь нет. Backend ImGui может использовать дескрипторы для своих нужд, но это не означает выполнения шестого дополнительного задания.

## 11. Что настраивает графический конвейер

`application::initialize()` создаёт `VkPipeline` один раз:

| Настройка | Значение | Смысл |
| --- | --- | --- |
| Shader stages | `cube.vert` и `cube.frag` | Положение вершин и цвет фрагментов |
| Vertex input | Почти пустой | Вершины берутся из массивов внутри шейдера |
| Input assembly | `TRIANGLE_LIST` | Каждые три элемента образуют треугольник |
| Polygon mode | `FILL` | Заполнять поверхности |
| Culling | `NONE` | Не удалять грани по ориентации |
| Multisampling | Один образец | MSAA здесь не включён |
| Depth test/write | Включены, сравнение `LESS` | Ближнее закрывает дальнее |
| Color write | RGBA разрешены | Записывать компоненты цвета |
| Blending | Не включён | Цвет куба не смешивается с прежним цветом |
| Viewport/scissor | Динамические | Размер задаётся при записи кадра |

После создания конвейера временные `VkShaderModule` уничтожаются. При завершении приложения `shutdown()` ждёт очередь и уничтожает конвейер и pipeline layout.

## 12. Что точно делает application::render()

`FrameData` содержит `framebuffer` — куда рисовать — и `command_buffer` — куда записать задания.

1. Код собирает `Model`, `View`, выбранную `Projection`, итоговую `MVP` и `tint`.
2. Цветовое изображение будет очищено до фона `(0.02, 0.08, 0.20, 1.0)`, глубина — до `1.0`.
3. `vkResetCommandBuffer` и `vkBeginCommandBuffer` начинают запись нового задания.
4. `vkCmdBeginRenderPass` указывает framebuffer, область кадра и значения очистки.
5. `vkCmdBindPipeline` выбирает конвейер куба.
6. `vkCmdSetViewport` и `vkCmdSetScissor` задают область текущего изображения.
7. `vkCmdPushConstants` передаёт MVP и цвет.
8. `vkCmdDraw(command_buffer, 36, 1, 0, 0)` задаёт 36 элементов и **один экземпляр** куба.
9. `vkCmdEndRenderPass` и `vkEndCommandBuffer` закрывают запись.

Render pass описывает использование цветового и глубинного изображений. Framebuffer связывает его с конкретными изображениями кадра. Фон появляется потому, что цветовое изображение очищается **каждый кадр**, а не потому, что окно имеет такой цвет само по себе.

## 13. Что делают шейдеры и откуда цвет внутри треугольника

Ключевые строки вершинного шейдера:

~~~glsl
vec3 position = positions[indices[gl_VertexIndex]];
gl_Position = drawData.mvp * vec4(position, 1.0);
vertexColor = (position * 0.5 + 0.5) * drawData.tint.rgb;
~~~

`vec4(position,1.0)` добавляет однородную координату `w = 1`: это **точка**, поэтому перенос на неё действует. `gl_Position` сообщает GPU преобразованное положение вершины. Это ещё не координата готового пикселя: дальше происходят отсечение, деление на `w`, переход к области кадра и растеризация.

Цвет получается из **локальных координат** вершины. Значения −1..1 выражение `position * 0.5 + 0.5` переводит в 0..1. Затем X, Y, Z используются как R, G, B и покомпонентно умножаются на выбранный цвет `tint`. Это процедурное правило: отдельные цвета восьми углов вручную не перечислены.

Внутри треугольника GPU **интерполирует** значения трёх углов, поэтому виден плавный градиент. Фрагментный шейдер получает интерполированный `vertexColor` и выдаёт `vec4(vertexColor,1.0)`. Альфа равна 1.

Даже после вычисления цвета фрагмент может не попасть в итог: если он дальше уже видимой поверхности, тест глубины его отклонит. `LESS` пропускает фрагмент с меньшей, то есть более близкой, глубиной.

## 14. Отправка GPU, показ и изменение размера

`graphics::internal::prepare()` получает изображение swapchain для текущего кадра. `submitAndPresent()` записывает команды ImGui и отправляет **два командных буфера**: сцену с кубом и интерфейс. `vkQueueSubmit` передаёт их в очередь GPU. `vkQueuePresentKHR` запрашивает показ готового изображения.

Семафоры согласуют получение изображения и готовность кадра к показу. Fence позволяет CPU дождаться завершения предыдущего использования командного буфера, прежде чем перезаписать его. CPU и GPU не обязаны выполнять свои части работы строго синхронно.

При изменении размера окна GLFW сообщает новый **размер framebuffer в пикселях**. Стартовый код пересоздаёт зависящие от размера ресурсы swapchain. Новый `aspect`, viewport и scissor берутся из актуального `swapchain_extent`.

### Короткий устный рассказ

> Мой вариант — куб. В вершинном шейдере заданы восемь его углов и список из 36 элементов для двенадцати треугольников. Каждый кадр ImGui обновляет параметры, C++ строит Model, View и выбранную Projection и объединяет их в MVP. MVP и цвет передаются через push constants. Вершинный шейдер применяет MVP и вычисляет цвет по локальному положению. GPU растеризует треугольники; фрагментный шейдер выдаёт цвет, а тест глубины оставляет ближние поверхности. Команды отправляются GPU, готовое изображение показывается через swapchain. Реализованы первые пять дополнительных пунктов; нескольких объектов с наборами дескрипторов нет.

## 16. Частые вопросы преподавателя

**Почему 8 углов, но 36 элементов?** Восемь уникальных позиций используются повторно. Шесть граней × два треугольника × три элемента = 36.

**Почему `vkCmdDraw`, а не `vkCmdDrawIndexed`?** Индексы находятся внутри вершинного шейдера, а не в Vulkan index buffer.

**Что делает вершинный шейдер?** Выбирает угол, применяет MVP и вычисляет его цвет.

**Что делает фрагментный шейдер?** Получает интерполированный цвет и выдаёт цвет фрагмента.

**Что такое MVP?** `Projection × View × Model`. Model размещает куб, View учитывает камеру, Projection создаёт положение для кадра.

**Зачем `w = 1` у точки?** Чтобы перенос можно было выполнить матрицей 4×4. В перспективе последующее деление на `w` создаёт уменьшение далёких объектов.

**Почему куб вращается вокруг центра?** Локальный центр — `(0,0,0)`. Масштаб и повороты действуют до переноса.

**Чем отличаются две проекции?** В перспективе дальнее выглядит меньше; в ортографии размер не зависит только от расстояния.

**Зачем нужен `aspect`?** Чтобы учитывать отношение ширины кадра к высоте и сохранять пропорции.

**Зачем буфер глубины?** Чтобы ближняя грань закрывала дальнюю. Он хранит глубину, а не цвет.

**Почему цвет меняется внутри грани без текстуры?** Разные цвета вершин интерполируются внутри треугольника.

**Что делает `tint`?** Покомпонентно умножает процедурный цвет вершины на выбранный в ImGui цвет.

**Почему анимация не зависит напрямую от FPS?** Время увеличивается на реальные секунды между кадрами, умноженные на скорость.

**Что такое push constants?** Маленький блок параметров текущего рисования; здесь 80 байт: MVP и цвет.

**Что такое `VkPipeline`?** Подготовленные правила рисования: шейдеры, треугольники, растеризация, глубина и цвет.

**Чем отличаются `vkCmdDraw` и `vkQueueSubmit`?** Первый записывает команду рисования; второй отправляет записанный буфер GPU.

**Зачем `vkQueuePresentKHR`?** Он запрашивает показ готового изображения в окне.

**Что не реализовано?** Несколько объектов с несколькими наборами дескрипторов, текстуры, загрузка моделей и освещение. Не приписывай их проекту.

## 17. Частые ошибки в объяснении

- «Куб уже находится на экране как набор 3D-точек». Нет: точки — данные сцены, экран показывает готовое двумерное изображение.
- «MVP рисует пиксели». Нет: она преобразует положения вершин. Пиксели появляются позже.
- «Шейдер передаёт MVP на GPU». Нет: C++ передаёт MVP, а шейдер **уже выполняется** на GPU и читает её.
- «Восемь вершин означают восемь пикселей». Нет: один треугольник может покрыть тысячи пикселей.
- «Глубина цвета равна буферу глубины». Нет: это совершенно разные понятия.
- «ImGui сам поворачивает куб». Нет: ImGui меняет переменную; C++ собирает MVP; GPU рисует следующий кадр.
- «`vkCmdDraw` сразу показывает куб». Нет: команда записывается, затем отправляется GPU, а готовый кадр отдельно показывается.

## 18. Проверка собственного понимания

Без подсказки расскажи путь **одного угла**: где хранится его локальная позиция; как он выбирается через `gl_VertexIndex`; почему к ней добавляют `w = 1`; как действует MVP; что делает растеризация; почему фрагмент может не пройти проверку глубины; когда кадр показывается в окне.

Если можешь объяснить эту цепочку простыми словами, ты понимаешь основу лабораторной. Названия отдельных структур Vulkan после этого учатся гораздо легче.
